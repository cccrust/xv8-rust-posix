# v0.6 - Memory Management Syscalls

Date: 2026-05-31

## New Syscalls (3 added, total 65)

| Num | Name | Description |
|-----|------|-------------|
| 62 | mmap | Memory mapping (stub - allocates virtual address only) |
| 63 | munmap | Remove memory mapping (stub) |
| 64 | mprotect | Set memory protection (stub) |

## Changes

### kernel/src/syscall.rs
- Added syscall numbers 62-64 to `Syscall` enum
- Added TryFrom cases and match arms for new syscalls

### kernel/src/sysproc.rs
- Implemented `sys_mmap`: allocates virtual address range from MMAP_BASE downward
- Implemented `sys_munmap`: stub that updates mmap_next
- Implemented `sys_mprotect`: stub returning success

### kernel/src/proc.rs
- Added `mmap_next: VA` field to `ProcData` for tracking next available mmap address
- Fixed `fork()` to reset child's mmap_next to MMAP_BASE
- Fixed `user_init()` to initialize mmap_next

### kernel/src/param.rs
- Added `MMAP_REGIONS` constant (16)
- Added `MMAP_BASE` constant

### kernel/src/kalloc.rs
- Added `alloc_page()` and `free_page()` public functions

### kernel/src/vm.rs
- Made `walk()` and `PageTableEntry` methods (`is_v`, `as_pa`, `flags`) public
- Added `From<VmError>` for `SysError`

### user/src/syscall.rs
- Added raw syscall wrappers for mmap, munmap, mprotect
- Added public wrapper functions

## Known Limitations
- mmap only reserves virtual address space; actual physical memory allocation is deferred
- munmap doesn't free physical pages
- mprotect is a stub (returns 0 without doing anything)

## Testing
- All 8 tests pass: fs, pipe, proc, fd, sbrk, cow, net, syscall
