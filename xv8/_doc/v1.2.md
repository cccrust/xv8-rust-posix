# v1.2 — ICMP Ping on xv8 (kernel ping socket + userspace ping tool)

Date: 2026-06-01

從 v1.1（DNS 查詢工具）到 v1.2，xv8 新增了 ICMP Echo Request/Reply 支援，實現了從使用者空間的 ping 工具，經核心 ping socket syscall，到 ICMP 協定棧的完整路徑。

---

## v1.2 重點：ICMP Ping 支援

### 工具鏈

```
ping tool (userspace) → user::pingsocket/pingsend/pingrecv
→ xv8 kernel PingTable → ICMP stack → E1000 → QEMU user-mode NAT → gateway
```

### 新增 Syscall

| Syscall | 號碼 | 功能 |
|---------|------|------|
| `pingsocket` | 108 | 開啟 ping socket，自動分配 ICMP identifier |
| `pingsend` | 109 | 發送 ICMP Echo Request 到指定 IP |
| `pingrecv` | 110 | 接收 ICMP Echo Reply（阻塞式） |

### 設計決策

- **專用 ping syscall**（非 raw socket）— 實作簡潔，與 UDP socket 模式一致
- **PingTable** 遵循 SocketTable 模式 — SpinLock 保護的固定大小陣列，receive queue 用 Channel sleep/wakeup
- **ICMP identifier 自動分配** — 單調遞增計數器（wrapping，跳過 0）
- **Sequence number 核心端自增** — 每次 `send()` 自動遞增，使用者空間不指定
- **IcmpHeader 欄位 `pub(crate)`** — 允許 PingTable 直接建構 ICMP header

### 異動摘要

| 檔案 | 變更 |
|------|------|
| `kernel/src/param.rs` | 新增 `NPING = 16` |

### PingTable 架構

- `MAX_PING_PAYLOAD = 64` bytes
- `MAX_PING_QUEUE_DEPTH = 8` — 每個 socket 最多 8 個待接收的 reply
- `NPING = 16` — 最多同時開啟 16 個 ping socket
- `receive()` 阻塞等待，使用 `proc::sleep(Channel::Buffer(...))` — 與 UDP SocketTable 一致
- `deliver()` 由 `icmp::handle_icmp()` 的 EchoReply 分支呼叫，以 ICMP identifier 查找對應 socket

### 驗證

- QEMU **11** 個整合測試全部 PASS（含 `_netping`）
- `ping 10.0.2.2` 成功收到 Echo Reply，回報 RTT

## 結論

v1.2 擴展了 xv8 的網路能力，從 UDP（v1.1）延伸到 ICMP：
1. **3 個新 syscall**（pingsocket/pingsend/pingrecv）提供乾淨的 ping 抽象
2. **PingTable** 遵循既有的 SocketTable 模式，保持核心一致性
3. **ping 工具** 是第一個 ICMP 使用者空間工具，驗證了 Echo Request/Reply 完整路徑
4. **listen 工具** 為 UDP 服務端鋪路
5. **netping 自動化測試** 確保 ICMP 路徑在 CI 中持續通過
