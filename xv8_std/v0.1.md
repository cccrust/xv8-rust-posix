# xv8_std v0.1 Implementation

## Scope
Minimal std implementation to run text-processing tools (cat, head, tail, grep, etc.) on xv8.

## What's Implemented

### Core I/O (✓)
- `std::io::Read` for `Fd` (stdin, stdout, stderr, files)
- `std::io::Write` for `Fd` (stdout, stderr)
- `std::io::BufRead` for stdin (lines(), read_line())
- `std::io::BufReader<File>` with `BufRead` (read_line(), lines())
- `syserr_to_io()` mapping `SysError` → `io::ErrorKind`

### Filesystem (✓)
- `File` with OpenOptions
- `Metadata` (size, permissions)
- `ReadDir` with `DirEntry`
- `SeekFrom` (Start, Current, End)

### Path (✓)
- `Path`, `PathBuf`
- `Display` implementation

### Environment (✓)
- `args()` returning `EnvArgs` from `user::syscall::Args::from_stack()`

### Process (partial)
- `exit()` - implemented
- `Command`, `Child`, `Stdio`, `ExitStatus` - stubs

## Blockers for xv8 Target

### 1. `user` crate is not `no_std`
**Issue:** `user/src/lib.rs` doesn't have `#![no_std]` and uses `std` features.

**Impact:** Cannot compile `xv8-libc` or `xv8-user-std` for `riscv64gc-unknown-none-elf`.

**Fix:** Add `#![no_std]` to `user/src/lib.rs` and replace `std` usage with `core`/`alloc`.

### 2. `alloc` crate availability
**Issue:** `riscv64gc-unknown-none-elf` target has no pre-built `alloc`.

**Fix:** Build with `-Z build-std=alloc,core` to compile `alloc` from source.

### 3. Workspace membership conflict
**Issue:** `user` is in `xv8` workspace; `posix/tools` is in `posix` workspace.

**Fix:** When building `posix/tools` for xv8 target, must use xv8's `user` crate via path dependency.
