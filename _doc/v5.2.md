# v5.2 cgroups v2 (Control Groups)

## 目標

在 xv8 中實作 Linux cgroups v2 的資源限制機制，提供 CPU、記憶體、PIDs 三種控制器，讓容器能限制與監控行程群組的資源使用。

## 設計

### 字元裝置 + 文字協定

xv8 缺乏 VFS 層，無法像 Linux 使用 cgroupfs 虛擬檔案系統。因此採用 **字元裝置 + 文字協定** 的方式：

- 裝置檔案：`/dev/cgroup`（major=2, minor=0）
- 寫入指令：透過 `write()` 傳送文字命令
- 讀取狀態：透過 `read()` 讀取所有 cgroup 的完整狀態
- 不需新 syscall

### CgroupTree 架構

```rust
static CGROUP_TREE: OnceLock<SpinLock<CgroupTreeInner>>;

struct CgroupTreeInner {
    cgroups: Vec<Option<Cgroup>>,  // 固定 16 個槽位
}

struct Cgroup {
    id: usize,
    name: String,
    procs: Vec<usize>,       // 歸屬的 process PID 列表
    cpu: CpuController,
    memory: MemoryController,
    pids: PidsController,
}
```

### 控制器

| 控制器 | Linux 對應 | 結構 |
|--------|-----------|------|
| CPU | `cpu.max` | `CpuController { max: usize, period: usize }` |
| Memory | `memory.max` | `MemoryController { max: usize }` |
| PIDs | `pids.max` | `PidsController { max: usize }` |

預設值：
- CPU period: 100000（與 Linux 相同）
- CPU max: 0（無限制）
- Memory max: 0（無限制）
- PIDs max: 0（無限制）

### 指令協定

寫入 `/dev/cgroup` 的文字命令：

| 指令 | 格式 | 範例 |
|------|------|------|
| `create` | `create <name>` | `create testgroup\n` |
| `attach` | `attach <pid> <name>` | `attach 42 testgroup\n` |
| `cpu.max` | `cpu.max <max> <period> <name>` | `cpu.max 50000 100000 testgroup\n` |
| `memory.max` | `memory.max <max> <name>` | `memory.max 1048576 testgroup\n` |
| `pids.max` | `pids.max <max> <name>` | `pids.max 10 testgroup\n` |

讀取回傳所有 cgroup 的詳細狀態，包含所有控制器參數與行程列表。

### 裝置分派

在 `sysfile.rs` 的 `sys_read()` / `sys_write()` 中，遇到 `FileType::Device { major: 2 }` 時，分別分派到 `cgroup::device_read()` 與 `cgroup::device_write()`。

```rust
// sysfile.rs: 寫入分派
CGROUP_DEV => crate::cgroup::device_write(addr, n),

// sysfile.rs: 讀取分派
CGROUP_DEV => crate::cgroup::device_read(addr, n),
```

## 測試結果

```
test cgroup ... ok
```

測試流程：
1. 開啟 `/dev/cgroup`
2. 建立名為 `testgroup` 的 cgroup
3. 設定 `cpu.max 50000 100000 testgroup`
4. 設定 `memory.max 1048576 testgroup`
5. 設定 `pids.max 10 testgroup`
6. 將自身行程 attach 到 `testgroup`
7. 讀取狀態，驗證包含所有設定的參數
8. 正常結束

## 已知限制

1. cgroup 僅儲存配置參數，尚未實作實際的資源控管（CPU 節流、記憶體回收、行程數限制）
2. 無巢狀 cgroup 支援（所有 cgroup 都是 root 的直屬子節點）
3. 無 cgroup 刪除指令
4. 無 procs/events 通知機制
5. 固定 16 個 cgroup 上限（`MAX_CGROUPS`）
