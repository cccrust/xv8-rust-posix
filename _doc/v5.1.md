# v5.1 命名空間 (Namespaces)

## 目標

為 xv8 加入容器基礎設施的第一步：Linux 風格的命名空間機制，支援 PID 和 UTS 命名空間的建立、隔離與查詢，並預留 mount/net/ipc/user/cgroup 命名空間的擴充點。

## 設計

### NsProxy

每個行程 (process) 擁有一個 `NsProxy` 結構，內部存放 7 種命名空間型別的 `Arc` 指標：

| 欄位 | 型別 | Linux 對應 |
|------|------|------------|
| `pid` | `Arc<PidNamespace>` | `CLONE_NEWPID` |
| `uts` | `Arc<UtsNamespace>` | `CLONE_NEWUTS` |
| `mount` | `Arc<MountNamespace>` | `CLONE_NEWNS` |
| `net` | `Arc<NetNamespace>` | `CLONE_NEWNET` |
| `ipc` | `Arc<IpcNamespace>` | `CLONE_NEWIPC` |
| `user` | `Arc<UserNamespace>` | `CLONE_NEWUSER` |
| `cgroup` | `Arc<CgroupNamespace>` | `CLONE_NEWCGROUP` |

`Clone` 實作為所有 `Arc` 的淺拷貝（共享同一命名空間物件）。  
`from_parent(parent, flags)` 根據 `flags` 中的 `CLONE_NEW*` 位元決定哪些命名空間要建立新實例。

### PID 命名空間

```rust
pub struct PidNamespace {
    id: NamespaceId,
    next_ns_pid: AtomicUsize,  // 從 1 開始
}
```

- `alloc_ns_pid()` 回傳此命名空間內的下一個可用 PID
- 子行程在 `fork()` / `clone_proc()` 時從父行程的 PID 命名空間取得 `ns_pid`
- `sys_getpid()` 暫時回傳 `tgid`（全域 PID），保留向 `ns_pid` 遷移的彈性
- `proc.rs` 的 `ProcInner` 新增 `ns_pid: Pid` 欄位

### UTS 命名空間

```rust
pub struct UtsNamespace {
    id: NamespaceId,
    data: SpinLock<UtsData>,  // hostname (最大 64 bytes)
}
```

- `clone_new()` 建立新 UTS 命名空間並拷貝父空間的主機名稱
- `sys_sethostname()` / `sys_gethostname()` 讀寫 `UtsNamespace.hostname`

### 根命名空間

系統啟動時透過 `OnceLock` 初始化一次，所有 `alloc()` 的新行程預設使用根命名空間。

## 已知限制

1. `setns` 回傳 `ENOSYS` — 需要 `/proc/<pid>/ns/<type>` 虛擬檔案系統支援
2. `getpid()` 暫時回傳 `tgid`（全域 PID）而非 `ns_pid`，因為核心執行緒佔用全域 PID 但未佔用命名空間 PID，導致兩計數器偏移
3. 非 UTS/PID 命名空間皆為空殼（僅有 `NamespaceId`），等待後續版本實作
4. `clone_proc()` 中的 `CLONE_NEWPID` 旗標會被傳遞給 `NsProxy::from_parent()`，但當 `getpid()` 回傳全域 PID 時，新命名空間的效果不明顯
5. 無巢狀 PID 命名空間支援（xv8 的排程器以全域 PID 爲主）
