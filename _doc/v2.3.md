# v2.3 — xv8-axum-smoke riscv64

**目標：在 QEMU 中跑通最小 HTTP server（GET / → 200 "ok"）**

---

## 依賴分析

### axum 對 riscv64 的依賴障礙

| 障礙 | 說明 | 解法 |
|------|------|------|
| tokio | 依賴 mio + OS 事件的非同步 runtime | xv8-async 替代（已有） |
| hyper | HTTP 協定實作，依賴 tokio | 自製最小 HTTP 回應 |
| http | HTTP 型別（HeaderMap, Method, Uri 等） | 直接處理 bytes |
| axum 本體 | Router, Handler trait, extractor | 手動解析 GET → 固定回應 |
| 本地 axum/tokio fork | 需要 `/Users/Shared/ccc/github/axum/` + `/tokio/` | 開發機器外不存在，無法編譯 workspace member |

**結論**：axum 完整移植不可行 — 依賴鏈過重、缺乏 OS event 機制。替代方案為自製最小 HTTP server，使用 xv8-async 執行 TCP 監聽。

---

## 這版做了什麼

### 最小 HTTP server (axum_smoke)
- 新增 `posix/tools/src/bin/axum_smoke.rs` — 基於 xv8-async 的極簡 HTTP server
- 監聽 loopback port 27003
- 讀取 HTTP request header，判斷是否為 GET 請求
- 回應 `HTTP/1.1 200 OK\r\n...\r\nok`（GET `/` → 200 "ok"）

### _http QEMU 測試
- 新增 `xv8/user/testbin/http.rs` — fork + exec axum_smoke
- `tcp_connect()` → send HTTP GET → recv response
- 驗證回應包含 `200 OK` 及 `ok`
- 整合進 testrunner：`/_http` 為第 13 個測試項目

### xv8-axum-smoke crate 更新
- 新增 `xv8-async` 為 riscv64 相依
- riscv64 main 實作與 axum_smoke 相同的 HTTP server
- 保留 host side axum+tokio 整合測試（需本地 fork 路徑）
- 因本地 axum/tokio 路徑不存在於開發機器，無法納入 workspace member
