# v3.5 — Performance: Futex Mutex, Chunk Allocator, Instant

## 目標

提升 xv8-user-std 的執行效能，減少 syscall 次數並簡化同步原語實作。

## 設計

### P1 — Futex-based Mutex

用標準的 3-state futex 協定取代原本的 spin-then-pipe Mutex：

| State | Value | 意義 |
|-------|-------|------|
| `UNLOCKED` | 0 | 無人持有 |
| `LOCKED` | 1 | 已鎖，無競爭者 |
| `CONTENDED` | 2 | 已鎖，有執行緒在 futex_wait 睡眠 |

**lock() 流程**：
1. CAS UNLOCKED → LOCKED → 成功立即返回
2. 自旋 100 次嘗試 CAS
3. swap CONTENDED，若之前不是 CONTENDED（即 LOCKED 但還沒人睡）→ futex_wait(CONTENDED)
4. 醒來後回到步驟 1

**unlock() 流程** (`MutexGuard::drop`)：
1. swap UNLOCKED
2. 若舊值為 CONTENDED → futex_wake(1)

完全消除 pipe FD 分配和記憶體足跡。

### P2 — Sbrk Chunk Pre-allocation Allocator

將原本每次 sbrk 的 allocator 改為 64KB chunk 預分配：

```rust
struct ChunkAlloc {
    base: AtomicUsize,
    offset: AtomicUsize,
}
```

- 每次 `alloc()` 在目前 chunk 內 bump offset
- 若 chunk 空間不足，sbrk 新的 64KB chunk
- CAS loop 確保 atomic bump
- `dealloc()` 仍為 no-op（bump allocator 特性）

64KB chunk 減少 ~256 倍的 sbrk syscall 次數（原本平均 256 bytes → 64KB）。

### P3 — Instant

xv8 無 `clock_gettime` syscall，`Instant::now()` 繼續使用 `xv8_libc::uptime()`（100Hz tick）。

## 影響分析

| 檔案 | 變更 |
|------|------|
| `xv8rust/xv8-user-std/src/sync.rs` | Mutex 改為 futex-based 3-state；移除 pipe/OnceCell/AtomicBool；新增 Debug impl for guards；新增 Barrier |
| `xv8rust/xv8-user-std/src/runtime.rs` | Xv8Alloc → ChunkAlloc（64KB chunk bump allocator） |

### 測試結果

9/9 QEMU core tests pass（含原有的 thread + 新增的 thread_v3）。

### 其他效能分析

轉變摘要：

| 面向 | 改進前 | 改進後 |
|------|--------|--------|
| Mutex 睡眠機制 | pipe read/write（2 syscalls + 2 FD） | futex_wait/wake（1 syscall + 0 FD） |
| 每個 Mutex 記憶體 | 6 words（locked, waiters, fds, pipe FDs） | 2 words（state + 0 for pipe） |
| 每次 alloc syscall | 1 sbrk syscall | 每 64KB 1 次 sbrk |
