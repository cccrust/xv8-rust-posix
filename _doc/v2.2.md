# v2.2 — xv8rust/net bridge + 網路工具移植 → QEMU 整合測試 ✅

## 目標

建立 `xv8rust/xv8-net/` crate，提供 `std::net` 相容 API 讓 `net/` 工具可在 riscv64 上編譯執行，並在 xv8 QEMU 內整合測試。

---

## 步驟 1：xv8rust 網路抽象層 ✅

建立 `xv8rust/xv8-net/` crate — 最小 `std::net` 相容層。

### 新增/修改檔案

| 檔案 | 狀態 | 行數 |
|------|------|------|
| `xv8rust/xv8-net/Cargo.toml` | **新增** | 7 行 |
| `xv8rust/xv8-net/src/lib.rs` | **新增** | 3 行 |
| `xv8rust/xv8-net/src/net.rs` | **新增** | 492 行 |
| `xv8rust/Cargo.toml` | 修改 | 加入 `xv8-net` 到 workspace members |

### xv8-net crate 架構

```
xv8rust/xv8-net/
├── Cargo.toml          # 依賴: xv8-user-std, xv8-libc
├── src/
│   ├── lib.rs          # #![no_std], pub mod net;
│   └── net.rs          # 492 行 - 完整 std::net 相容層
```

### 提供的型別與 API

| 型別 | 匹配 std::net 方法 |
|------|-------------------|
| `Ipv4Addr` | `new`, `octets`, `UNSPECIFIED`/`LOCALHOST`/`BROADCAST`, Display, FromStr, From\<[u8;4]\>, Into\<u32\> |
| `IpAddr` | `V4(Ipv4Addr)`, `is_unspecified`, `is_loopback` |
| `SocketAddrV4` | `new`, `ip`, `port` |
| `SocketAddr` | `V4(SocketAddrV4)`, `new`, `ip`, `port`, Display, FromStr |
| `ToSocketAddrs` | 支援 `SocketAddr`, `(IpAddr,u16)`, `(&str,u16)`, `&str`, `String`, `u16` |
| `TcpStream` | `connect`, `peer_addr`, `set_read/write_timeout`, `set_nodelay`, `shutdown`, `try_clone`, `Read`+`Write` |
| `TcpListener` | `bind`, `accept`, `local_addr`, `set_nonblocking`, `incoming()` |
| `UdpSocket` | `bind`, `send_to`, `recv_from`, `set_read/write_timeout`, `fd` |
| `Shutdown` | `Read`, `Write`, `Both` |
| `lookup_host` | IP 直接解析；DNS 待後續整合 |

### Re-export

- `Read`, `Write`, `Error`, `ErrorKind`, `Result` — 來自 `xv8_user_std::io`
- `Duration` — 來自 `xv8_user_std::time`

### 設計

- `#![no_std]` + `extern crate alloc`
- 內部委派（delegation）至 `xv8_user_std::net` 基礎型別
- `set_read_timeout` / `set_write_timeout` 為 no-op stub（xv8 核心無 per-socket timeout）
- 轉換層在位址型別間轉換

### 編譯驗證

```bash
cargo build --release -p xv8-net                            # host ✅
cargo build --release -p xv8-net --target riscv64gc-unknown-none-elf  # riscv64 ✅
# 零警告，零錯誤
```

## 步驟 3：QEMU 整合測試 ✅

### `xv8/mkfs.sh` 修改

- 新增 net tools 建置步驟（riscv64 cross-compile via `-Zbuild-std`）
- 7 個 net binaries 加入 `fs.img`：`dns`, `host`, `ntp`, `tcpclient`, `tcpserver`, `tftp`, `whois`
- 移除 xv8-native `dns` binary（net tools dns 取代）

### `_nettools` 測試

| 檔案 | 說明 |
|------|------|
| `xv8/user/testbin/nettools.rs` | QEMU testbin：fork+exec tcpserver → nanosleep 500ms → fork+exec tcpclient → wait/kill/驗證退出碼 |
| `xv8/user/testbin/testrunner.rs` | 加入 `/_nettools` 至 `const TESTS` |
| `xv8/user/Cargo.toml` | 註冊 `_nettools` binary |

### tcpclient 堆疊溢位修復

`net/tools/src/bin/tcpclient.rs` — `[0u8; 65536]` stack array → `vec![0u8; 65536]` heap allocation。
xv8 使用者堆疊僅 `USERSTACK = 4` pages（16 KB），64 KB 堆疊陣列造成 page fault，行程以 exit code -1 終止。

### root `test.sh` 重寫

全專案合併測試驅動：

| 階段 | 內容 |
|------|------|
| Phase 1 | stash `posix/.cargo/config.toml` → POSIX host build |
| Phase 2 | shell 測試 (33/33) + core tools 測試 (21/21) |
| Phase 3 | POSIX cargo test |
| Phase 4 | net host tests（libnet + dns/ntp/whois/tcp smoke） |
| Phase 5 | restore config → riscv64 cross-compile：posix, xv8rust, net tools |
| Phase 6 | xv8 QEMU 整合測試 (12/12) |
| Phase 7 | pass/fail 計數報告 |

### 驗收

```bash
./test.sh
# Results: 9 passed, 0 failed
```

### 關鍵脈絡

- kernel `tcp_connect()` 為無限 busy-wait，無 timeout
- `set_read_timeout` / `set_write_timeout` 在 xv8-net 為 no-op
- riscv64 編譯需要 nightly + `build-std`
- `posix/.cargo/config.toml` 設有 `[build] target = "riscv64gc-unknown-none-elf"`，host build 前必須 stash
