# v3.2 — Futex-based Park + Condvar

## 目標

在 xv8 kernel 實作 `futex` syscall（FUTEX_WAIT/FUTEX_WAKE），並將 `xv8-user-std` 中 thread parking 與 Condvar 從 pipe 機制改為 futex-based，移除 per-thread pipe FD，減少 file descriptor 用量並支援多 waiter。

## 設計總覽

### 動機

原本 thread park/unpark 與 Condvar 都依賴 pipe：
- 每個 thread 建立一個 private pipe（2 個 FD）
- Condvar 建立一個 pipe（2 個 FD）
- park = pipe read (block)，unpark = pipe write
- Condvar wait = pipe read，notify = pipe write

問題：
1. **FD 用量大**：NPROC=64 時最多 128 個 FD 用於 parking
2. **Condvar 單一 waiter**：pipe-based Condvar 的 `notify_one` 無法精確控制只喚醒一個 waiter（pipe write 會讓所有 reader 競爭）
3. **多餘系統呼叫**：pipe read/write 比 futex 重（需經過 VFS + pipe buffer 管理）

### Futex 方案

Linux futex（Fast Userspace Mutex）核心概念：
```
futex(uaddr, FUTEX_WAIT, val):
    原子檢查 *uaddr == val
    如果是 → 睡在 uaddr 這個 channel 上
    如果不是 → 回傳 EAGAIN

futex(uaddr, FUTEX_WAKE, count):
    喚醒最多 count 個睡在 uaddr 上的 thread
    回傳實際喚醒數量
```

使用者空間自行管理 `uaddr` 處的狀態值，kernel 只提供原子的 check-and-sleep 與 wake。

## P1 — Kernel Futex Syscall

### 1.1 Syscall Number

```rust
// xv8/kernel/src/syscall.rs
Futex = 123,
```

### 1.2 Channel::Address Variant

原本 `sleep(channel)` 與 `wakeup(channel)` 使用 `Channel` enum。新增 `Address` variant 存放使用者空間位址：

```rust
// xv8/kernel/src/proc.rs
pub enum Channel {
    Pid(Pid),
    Address(usize),
    // ...
}
```

每個 sleeping process 的 `channel` 欄位存 `Some(Channel::Address(addr))`，`FUTEX_WAKE` 透過 `wakeup(Channel::Address(addr))` 喚醒對應 thread。

### 1.3 wakeup_n()

原 `wakeup()` 喚醒所有睡在 channel 上的 process。新增 `wakeup_n(channel, count)` 最多喚醒 N 個：

```rust
pub fn wakeup_n(channel: Channel, count: usize) -> usize {
    let current = current_proc_opt();
    let mut woken = 0;
    for proc in PROC_TABLE.iter() {
        if woken >= count { break; }
        if current.is_some_and(|p| ptr::eq(p, proc)) { continue; }
        let mut inner = proc.inner.lock();
        if inner.state == Sleeping && inner.channel == Some(channel) {
            inner.state = Runnable;
            woken += 1;
        }
    }
    woken
}
```

### 1.4 sys_futex

```rust
// xv8/kernel/src/sysproc.rs
pub fn sys_futex(args: &SyscallArgs) -> Result<usize, SysError> {
    let addr = args.get_addr(0);       // uaddr
    let op = args.get_int(1) as i32;  // FUTEX_WAIT=0, FUTEX_WAKE=1
    let val = args.get_int(2) as u32; // expected / wake count

    match op & 0xf {
        0 => { // FUTEX_WAIT
            let (proc, mut data) = current_proc_and_data_mut();
            let mut buf = [0u8; 4];
            // 從使用者 pagetable 讀取 4 bytes
            data.pagetable_mut().copy_from(addr, &mut buf)?;
            let curr = u32::from_le_bytes(buf);
            if curr != val {
                return Err(SysError::ResourceUnavailable); // EAGAIN
            }
            drop(data);
            let mut inner = proc.inner.lock();
            inner.channel = Some(Channel::Address(addr.as_usize()));
            inner.state = ProcState::Sleeping;
            let context = unsafe { &mut proc.data_mut().context };
            inner = proc::sched(inner, context);
            inner.channel = None;
            Ok(0)
        }
        1 => { // FUTEX_WAKE
            let channel = Channel::Address(addr.as_usize());
            let woken = wakeup_n(channel, val as usize);
            Ok(woken)
        }
        _ => Err(SysError::NotImplemented),
    }
}
```

FUTEX_WAIT 流程：
1. 從使用者 pagetable 複製 4 bytes 到 kernel
2. 比較 `*uaddr` 與 `val`
3. 不相同 → 回傳 EAGAIN (`-11`)
4. 相同 → 設 channel = Address(uaddr)，state = Sleeping，呼叫 `sched()`
5. 被喚醒後清除 channel，回傳 0

FUTEX_WAKE 流程：
1. 用 `wakeup_n(Channel::Address(addr), count)` 喚醒最多 count 個 waiter
2. 回傳實際喚醒數量

## P3 — thread::park/unpark (Futex 3-State Protocol)

### 3.1 狀態機

使用 3-state protocol 避免「喚醒遺失」race：

```
EMPTY   = 0 — 無通知，thread 不在等待
NOTIFIED = 1 — 已通知（unpark 被呼叫過）
PARKED  = 2 — thread 正在 futex_wait 中
```

```
park():
    if swap(EMPTY) == NOTIFIED → 已通知，立即回傳
    loop:
        compare_exchange(EMPTY → PARKED)
        futex_wait(PARKED)        ← kernel 原子檢查 *addr == PARKED
        if swap(EMPTY) == NOTIFIED → 被喚醒，回傳
        ← spurious wakeup，繼續 loop

unpark():
    if swap(NOTIFIED) == PARKED → thread 在等，呼叫 futex_wake
```

### 3.2 TCB 修改

```rust
// before (pipe-based)
struct Tcb {
    park_r: usize,      // pipe read FD
    park_w: usize,      // pipe write FD
    args_ptr: usize,
}

// after (futex-based)
struct Tcb {
    park: AtomicU32,    // EMPTY / NOTIFIED / PARKED
    args_ptr: usize,
}
```

主 thread 使用全域 `MAIN_PARK: AtomicU32`（tp=0 時）。

### 3.3 park() 實作

```rust
pub fn park() {
    let addr = current_park_addr();
    let state = unsafe { &*(addr as *const AtomicU32) };

    // fast path: 消耗既有的 notification
    if state.swap(EMPTY, Acquire) == NOTIFIED {
        return;
    }

    while state.compare_exchange(EMPTY, PARKED, Relaxed, Relaxed).is_ok() {
        // 成功設為 PARKED，等待 futex_wake
        xv8_libc::futex(addr as *const u32, FUTEX_WAIT, PARKED);
        if state.swap(EMPTY, Acquire) == NOTIFIED {
            return;
        }
        // spurious wakeup → 繼續 loop
    }

    // compare_exchange 失敗（狀態是 NOTIFIED），消耗 notification
    state.swap(EMPTY, Acquire);
}
```

### 3.4 unpark() 實作

```rust
pub fn unpark(&self) {
    let state = unsafe { &*(self.park_addr as *const AtomicU32) };
    if state.swap(NOTIFIED, Release) == PARKED {
        xv8_libc::futex(self.park_addr as *const u32, FUTEX_WAKE, 1);
    }
}
```

### 3.5 spawn() 簡化

移除了 park pipe 的建立與關閉：

```rust
pub fn spawn<F, T>(f: F) -> JoinHandle<T> {
    // 不再需要 park_fds pipe
    let join_fds = pipe();
    let tcb = Box::new(Tcb { park: AtomicU32::new(EMPTY), args_ptr });
    let tcb_ptr = Box::into_raw(tcb);
    let park_addr = tcb_ptr as usize; // park 是 Tcb 第一個欄位
    // clone(CLONE_VM | CLONE_SIGHAND | CLONE_SETTLS, stack_top, 0, tcb_ptr)
    // child_entry 不再需要 close(park_w)
    JoinHandle {
        thread: Thread { id, join_fd, park_addr },
        result_ptr,
    }
}
```

## P4 — Condvar (Futex Counter)

### 4.1 設計

Condvar 用一個 `AtomicU32` counter 搭配 futex：

```
notify_one() / notify_all():
    counter.fetch_add(1, Release)
    futex_wake(&counter, 1)         // notify_one
    futex_wake(&counter, i32::MAX)  // notify_all

wait(guard):
    count = counter.load(Relaxed)
    drop(guard)                           // 釋放 mutex
    futex_wait(&counter, count)           // 等 counter 改變
    guard = mutex.lock()                  // 重新取得 mutex
```

### 4.2 實作

```rust
pub struct Condvar {
    counter: AtomicU32,
}

impl Condvar {
    pub const fn new() -> Self {
        Self { counter: AtomicU32::new(0) }
    }

    pub fn wait<'a, U>(&self, guard: MutexGuard<'a, U>) -> LockResult<MutexGuard<'a, U>> {
        let count = self.counter.load(Relaxed);
        let mutex = guard.mutex;
        drop(guard);

        let ptr = &self.counter as *const AtomicU32 as *const u32;
        xv8_libc::futex(ptr, FUTEX_WAIT, count); // EAGAIN = spurious wakeup

        mutex.lock()
    }

    pub fn notify_one(&self) {
        self.counter.fetch_add(1, Release);
        let ptr = &self.counter as *const AtomicU32 as *const u32;
        xv8_libc::futex(ptr, FUTEX_WAKE, 1);
    }

    pub fn notify_all(&self) {
        self.counter.fetch_add(1, Release);
        let ptr = &self.counter as *const AtomicU32 as *const u32;
        xv8_libc::futex(ptr, FUTEX_WAKE, i32::MAX as u32);
    }
}
```

運作原理：
1. `notify_one()` 增加 counter 並喚醒一個 waiter
2. `wait()` 儲存目前的 counter 值，釋放 mutex，等待 counter 改變
3. 若 `notify_one()` 在 `wait()` 儲存 counter 之後、進入 futex 之前被呼叫，counter 增加，futex 看見 `*counter != count` → EAGAIN，不會 sleep
4. `notify_all()` 增加 counter 並喚醒所有 waiter

### 已知限制

1. **僅 FUTEX_WAIT / FUTEX_WAKE**：未實作 `FUTEX_REQUEUE`、`FUTEX_CMP_REQUEUE`、`FUTEX_WAIT_BITSET` 等進階操作
2. **FUTEX_WAIT 無 timeout**：kernel 的 `sleep()` 無 timeout 參數，不支援 `FUTEX_WAIT` timeout（可透過 `park_timeout` 或 `Condvar::wait_timeout` 日後擴充）
3. **使用者空間仍需 atomic 操作**：park token (AtomicU32) 在 riscv64gc 上產生 `lr.w`/`sc.w`（A extension），QEMU `-cpu max` 支援，但不見於所有硬體實作
