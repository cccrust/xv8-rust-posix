# v2.1 — xv8-async riscv64 編譯 + IO reactor

**目標：讓 xv8-async 可為 riscv64 target 編譯，並補上 async TCP IO 層。**

---

## 這版做了什麼

### riscv64 編譯驗證
- `xv8-async` 直接以 `riscv64gc-unknown-none-elf` 編譯通過
- 原本 `xv8rust/Cargo.toml` 的 `[patch.crates-io] tokio` 指向已移除的本地路徑，以及 `xv8-axum-smoke` workspace member 因依賴本地 axum/tokio source 而無法解析
- **修正**：暫時從 workspace 中移除 `xv8-axum-smoke` member，移除 tokio patch（v2.3 再重新加入）

### AsyncTcpListener / AsyncTcpStream
- 新增 `xv8-async/src/net.rs`，提供：
  - `AsyncTcpListener::bind(addr)` — 建立 async TCP listener
  - `AsyncTcpListener::accept() → Accept` future — 接受連線（目前 blocking，返回 Ready）
  - `AsyncTcpStream::connect(addr)` — 連接到遠端
  - `AsyncTcpStream::read(buf) → ReadFuture` — blocking read wrapped as future
  - `AsyncTcpStream::write(buf) → WriteFuture` — blocking write wrapped as future
- 內部使用 `xv8-user-std::sync::Mutex<TcpStream>` 處理 `&self` → `&mut self` 的 interior mutability

### IO reactor
- 目前 xv8 kernel 無 `epoll`/`select`/`kqueue`，TCP syscall 為 blocking
- IO wrapper 回傳 `Poll::Ready(...)` 直接執行 blocking 操作
- 在單執行緒 executor 中，accept/read/write 會阻塞 executor → 一次只能處理一個連線
- 當 kernel 支援 poll/select 後可改為非阻塞（v2.3 規劃）

### xv8rust 工作空間調整
- `xv8-axum-smoke` 從 workspace members 中移除，因依賴本地 `axum`/`tokio` source 路徑
- `[patch.crates-io] tokio` 一併移除
- 未來 v2.3 重新加入時需將本地 source 補回
