# v3.0 — 支援 `std::thread`（完整 kernel clone() 方案）

## 目標

在 xv8 kernel 實作 `clone()` syscall（類 Linux），讓使用者空間能建立真正的 OS thread（共享記憶體、獨立執行、可同時跑在不同 hart 上）。最終讓 `xv8-user-std::thread` 提供 `spawn()`、`JoinHandle`、`park()`/`unpark()`、`sleep()`、`yield_now()`。

## 設計總覽

Linux `clone()` 架構，簡化版本：

```
clone(flags, stack, ptid, tls, ctid)
  flags:
    CLONE_VM      = 共享使用者 pagetable（thread 的核心）
    CLONE_THREAD  = 同一 thread group（getpid 傳 tgid）
    CLONE_SIGHAND = 共享 signal actions
    CLONE_FILES   = 共享 FD table
    CLONE_SETTLS  = 設定 tp register（TLS pointer）
```

**不支援的 flags**（xv8 無對應功能）：
- `CLONE_NEWNS` / `CLONE_NEWPID` / 其他 namespace flags
- `CLONE_CHILD_SETTID` / `CLONE_PARENT_SETTID`（可加但不需要）
- `CLONE_VFORK`（vfork 語意）

**實作分 5 期：**

```
P1: 核心基礎 ─  clone(CLONE_VM) + tgid + exit_group
P2: 資源共享 ─  CLONE_FILES + CLONE_SIGHAND
P3: TLS + park/unpark ─ CLONE_SETTLS + pipe+epoll parking
P4: 使用者端 ─  xv8-user-std::thread API
P5: 測試 ─  多執行緒 smoke test + regression
```

## P1 — Kernel: tgid + clone(CLONE_VM) + exit_group

### 1.1 加 `tgid` 到 `ProcInner`

```rust
pub struct ProcInner {
    pub pid: Pid,    // thread ID (唯一)
    pub tgid: Pid,   // thread group ID (同 group 的所有 thread 相同)
    // ... rest unchanged
}
```

- `clone()`：`thread.pid = Pid::alloc()`（唯一），`thread.tgid = parent.tgid`
- `getpid()` 傳回 `tgid`（POSIX 語意）
- 新增 `gettid()` syscall（Linux `SYS_gettid`）

### 1.2 clone() syscall 核心

kernel `clone()` 流程：

```
sys_clone(flags, stack, ptid, tls, ctid):
  1. PROC_TABLE.alloc() → 取一個 unused 的 proc slot
  2. 設置 child 的 kernel stack、context
  3. 分配 child 的 trapframe（獨立 page，不共享）
  4. 如果 flags & CLONE_VM:
       child.pagetable = parent.pagetable（共享同一 Uvm）
       不複製記憶體、不 COW
  5. 否則: 同 fork() 的完整 pagetable 複製（保留相容性）
  6. 如果 flags & CLONE_THREAD:
       child.tgid = parent.tgid（同 group）
  7. 複製 trapframe 暫存器（child a0 = 0）
  8. child 設為 Runnable
  9. 回傳 child pid
```

**Uvm 共享實作：**

當前 `ProcData.pagetable: Option<Uvm>` 為每個 process 獨佔。為支援共享：

```rust
pub struct ProcData {
    pub pagetable: Option<Uvm>,       // 非 CLONE_VM: 獨佔擁有
    pub pagetable_ref: Option<Arc<Uvm>>, // CLONE_VM: Arc 共享
    // ...
}
```

或更簡單的方式：在 `Uvm` 上直接加 refcount：

```rust
pub struct Uvm {
    pub inner: PageTable,
    refcount: &'static AtomicUsize,  // Box leaked
}

impl Uvm {
    pub fn try_new() -> Result<Self, VmError> {
        let inner = PageTable::try_new()?;
        let rc = Box::leak(Box::new(AtomicUsize::new(1)));
        Ok(Uvm { inner, refcount: rc })
    }
    
    pub fn share(&self) -> Self {
        self.refcount.fetch_add(1, Ordering::Relaxed);
        Uvm { inner: self.inner, refcount: self.refcount }
    }
    
    pub fn free(&mut self, size: usize) {
        if self.refcount.fetch_sub(1, Ordering::Relaxed) == 1 {
            // 最後一個 thread，真的釋放
            self.free_inner(size);
        }
    }
}
```

**`proc_free` 修改：**

```rust
pub fn free(&self, mut inner: SpinLockGuard<'_, ProcInner>) {
    let data = unsafe { self.data_mut() };
    // ...
    if let Some(uvm) = data.pagetable.take() {
        uvm.proc_free(data.size);  // 只有最後一個 thread 才真正 free
    }
    // ...
}
```

### 1.3 `exit_group()` syscall

當一個 thread 呼叫 `exit()`，只有該 thread 退出。  
`exit_group(status)` 殺掉整個 thread group：

```rust
pub fn exit_group(status: isize) -> ! {
    let proc = current_proc();
    let tgid = proc.inner.lock().tgid;
    
    // 把所有同 tgid 的 thread 標成 killed
    for p in PROC_TABLE.iter() {
        let inner = p.inner.lock();
        if inner.tgid == tgid && inner.state != ProcState::Unused {
            drop(inner);
            p.data().signals.send_signal(SIGKILL);
        }
    }
    
    // 然後 exit 自己
    exit(status);
}
```

### 1.4 `wait()` 修改

- `wait()` 目前只等 child process。對 thread 可用 `waitid()` 或 Linux `__WCLONE` flag。
- 簡化：thread exit 時，找 parent 的 thread group 中任一 thread 做 wakeup。

### 1.5 `kill()` 修改

- `kill(pid)`：如果 pid 對應的是 thread，只殺該 thread
- `kill(-tgid)` 或 SIGKILL 殺整個 group

### 1.6 Syscall 註冊

```rust
// syscall.rs
const SYS_CLONE: usize = 120;
const SYS_GETTID: usize = 121;
const SYS_EXIT_GROUP: usize = 122;
```

## P2 — CLONE_FILES + CLONE_SIGHAND

### 2.1 FD table 共享

現狀：
```rust
pub open_files: [Option<File>; NOFILE],  // ProcData 內嵌陣列
```

改成 `Arc<SpinLock<...>>`：

```rust
pub open_files: Option<Arc<SpinLock<[Option<File>; NOFILE]>>>,
```

- 非 clone: `open_files: Some(Arc::new(SpinLock::new([None; NOFILE])))`
- CLONE_FILES: child 的 `open_files = parent.open_files.clone()`（Arc 共享）
- 存取方式改成 `self.open_files.as_ref().unwrap().lock()`
- 影響範圍：所有 `proc.rs`、`sysfile.rs`、`sysproc.rs` 中存取 `open_files` 的地方（約 20-30 處）

### 2.2 Signal actions 共享

現狀：
```rust
pub sigactions: [signal::SigAction; signal::SIGNAL_MAX],  // 內嵌陣列
```

改成：

```rust
pub sigactions: Option<Arc<SpinLock<[signal::SigAction; signal::SIGNAL_MAX]>>>,
```

### 2.3 不共享的欄位

- `kstack` — 每個 thread 獨立 kernel stack（已由 `PROC_TABLE.alloc()` 分配）
- `trapframe` — 每個 thread 獨立
- `context` — 每個 thread 獨立
- `size` — 共享記憶體所以 `size` 需由 pagetable refcount 管理
- `cwd` — fork/exec 語意下通常共享
- `umask` — 共享
- `env` — 共享
- `uid/gid/euid/egid/suid/sgid` — 共享
- `pgrp` — 共享

## P3 — TLS + park/unpark

### 3.1 CLONE_SETTLS

在 clone syscall 中，若 `flags & CLONE_SETTLS`，則：

```rust
// tls 參數是使用者空間的 TCB 位址
child_trapframe.tp = tls;
```

xv8 kernel 的 trampoline 已正確保存/還原使用者 tp register，不需任何修改。

使用者空間的 TLS 設定：
```rust
// thread creation:
let stack = mmap(0, STACK_SIZE, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, ...);
let tcb = stack + STACK_SIZE - TCB_SIZE;
// 設定 tp = tcb
// clone(CLONE_VM | CLONE_SETTLS, stack + STACK_SIZE, ..., tcb, ...)
```

### 3.2 park/unpark via pipe+epoll

每個 thread 一個 private pipe：

```rust
thread_local! {
    static PARK_PIPE: (RawFd, RawFd) = pipe2(O_NONBLOCK).unwrap();
}

fn park() {
    let (read_fd, _) = *PARK_PIPE;
    let mut buf = [0u8; 8];
    // 從 pipe read end 讀，block 直到 unpark 寫資料
    let _ = read(read_fd, &mut buf);
}

fn unpark() {
    let (_, write_fd) = *PARK_PIPE;
    let one = 1u64;
    let _ = write(write_fd, &one.to_le_bytes());
}
```

不需 kernel 修改，純使用者空間實作。搭配 `epoll_wait` 可實作 `park_timeout`。

### 3.3 thread::sleep

使用 `nanosleep()` syscall（已存在），封裝成：

```rust
fn sleep(dur: Duration) {
    let (sec, nsec) = (dur.as_secs(), dur.subsec_nanos());
    nanosleep(sec, nsec);
}
```

### 4.2 clone 封裝

`xv8-libc` 和 `xv8/user/src/syscall.rs` 加：

```rust
// xv8-libc
pub unsafe fn clone(flags: usize, stack: usize, ptid: usize, tls: usize, ctid: usize) -> isize {
    let ret: isize;
    unsafe {
        asm!(
            "li a7, 120",  // SYS_CLONE
            "ecall",
            // ... parameter passing
            inout("a0") flags => ret,
            in("a1") stack,
            in("a2") ptid,
            in("a3") tls,
            in("a4") ctid,
        );
    }
    ret
}
```

## P5 — 測試

### 5.1 `_thread` testbin

```rust
#![no_std]
#![no_main]

#[unsafe(no_mangle)]
fn main(_args: Args) {
    // Test 1: spawn + join
    let handle = thread::spawn(|| {
        42
    });
    assert_eq!(handle.join(), 42);
    
    // Test 2: shared memory
    let counter = Arc::new(AtomicUsize::new(0));
    let c = counter.clone();
    let handle = thread::spawn(move || {
        c.fetch_add(1, Ordering::SeqCst);
    });
    handle.join();
    assert_eq!(counter.load(Ordering::SeqCst), 1);
    
    // Test 3: park/unpark
    let t = thread::current();
    thread::spawn(move || {
        thread::sleep(Duration::from_millis(10));
        t.unpark();
    });
    thread::park();
    
    // Test 4: multiple threads
    let mut handles = Vec::new();
    for i in 0..4 {
        handles.push(thread::spawn(move || i * 2));
    }
    for (i, h) in handles.into_iter().enumerate() {
        assert_eq!(h.join(), i * 2);
    }
    
    println!("_thread: PASS");
}
```

### 已知限制

1. **NPROC=64** — 最多 64 個執行緒（包含所有 process + thread）。需要加大到 128
2. **使用者 stack 大小** — 預設 16KB，thread stack 需 `mmap` 自訂（64KB 以上）
3. **CSR trap for atomics** — `Arc` 的原子操作在 riscv64 使用者態會 trap（csrr sstatus）。kernel 的 CSR 模擬已實作，但可能影響效能
4. **無 preemptive thread scheduling** — 已由 timer interrupt 提供（所有 process 共享）
5. **`mmap` 不能指定位址** — 目前只支援 `mmap(0, ...)`（由 kernel 自動分配位址）
