# v2.4 — xv8 QEMU Async Runtime (block_on + Sleep)

## Summary

Created a minimal async executor testbin (`_async`) that runs on xv8 QEMU, demonstrating async/await with `block_on` and `Sleep` futures. All 14/14 QEMU tests pass (added `_async`), root `test.sh` 9/9.

## Key Technical Challenge: `csrr sstatus` in User Mode

The `riscv64gc-unknown-none-elf` target's compiler generates `csrr sstatus` (supervisor CSR read) for ALL `core::sync::atomic` operations:

- `AtomicBool::compare_exchange` → `csrr sstatus` + LR/SC
- `AtomicUsize::fetch_add` → `csrr sstatus` + `amoadd`
- `Arc::drop` → `csrr sstatus` + refcount decrement
- `Weak::upgrade` → `csrr sstatus` + `compare_exchange`

This traps in user mode as illegal instruction (`scause=0x2`). **Solution: zero atomics.** No `Arc`, `Weak`, `AtomicBool`, or `AtomicUsize` anywhere.

## Architecture

`xv8/user/testbin/async.rs` — self-contained, zero external deps:

- **`block_on`** — takes any `Future<Output = T>`, pins on stack via `Pin::new_unchecked`, spin-polls with `nanosleep(1ms)` between iterations
- **`Sleep`** — stores a `deadline_ticks: u64`, returns `Poll::Pending` until `uptime() >= deadline_ticks`
- **Dummy waker** — `RawWakerVTable` with no-op wake (safe because poll-loop handles everything)
- **6 tests**: `block_on value`, `block_on expr`, `sleep 10ms`, `two sleeps`, `loop+sleep`, `nested block_on`
