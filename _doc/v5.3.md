# v5.3 安全隔離 (Capabilities + seccomp)

## 目標

為 xv8 加入容器化的安全基礎：Capabilities 提供細粒度權限控制，seccomp 提供系統呼叫過濾。兩者合併為容器的安全隔離層。

## 設計

### Capabilities (5-set model)

每個 process 擁有 5 組 capability set，比照 Linux 的完整模型：

| Set | 用途 | 儲存方式 |
|-----|------|---------|
| **Effective (eff)** | 當前生效的權限 | `u64` bitmask |
| **Permitted (prm)** | 允許提升的權限上限 | `u64` bitmask |
| **Inheritable (inh)** | 可被子 process 繼承 | `u64` bitmask |
| **Bounding (bnd)** | 子 process 的上限 | `u64` bitmask |
| **Ambient (amb)** | 非特權程式的 cap 保持 | `u64` bitmask |

```rust
#[derive(Debug, Clone)]
pub struct CapabilityState {
    pub effective: u64,   // 當前生效
    pub permitted: u64,   // 允許提升的
    pub inheritable: u64, // 可繼承
    pub bounding: u64,    // 子 process 上限
    pub ambient: u64,     // 非特權程式保持
}
```

**常數與規則**：

| 常數 | Bit | Linux 對應 |
|------|-----|-----------|
| `CAP_CHOWN` | 0 | 變更檔案擁有者 |
| `CAP_DAC_OVERRIDE` | 1 | 跳過 DAC 權限檢查 |
| `CAP_DAC_READ_SEARCH` | 2 | 跳過 DAC 讀取檢查 |
| `CAP_FOWNER` | 3 | 以 owner 身份操作 |
| `CAP_FSETID` | 4 | 保留 setuid/setgid |
| `CAP_KILL` | 5 | 發送訊號給任何 process |
| `CAP_SETGID` | 6 | 變更 GID |
| `CAP_SETUID` | 7 | 變更 UID |
| `CAP_SETPCAP` | 8 | 設定 capabilities |
| `CAP_NET_BIND_SERVICE` | 10 | 綁定特權 port (<1024) |
| `CAP_NET_BROADCAST` | 11 | 網路廣播 |
| `CAP_NET_ADMIN` | 12 | 網路管理 |
| `CAP_NET_RAW` | 13 | 原始 socket |
| `CAP_IPC_LOCK` | 14 | 鎖定記憶體 |
| `CAP_IPC_OWNER` | 15 | IPC owner 覆寫 |
| `CAP_SYS_CHROOT` | 18 | chroot |
| `CAP_SYS_PTRACE` | 19 | ptrace |
| `CAP_SYS_ADMIN` | 21 | 系統管理 |
| `CAP_SYS_RESOURCE` | 24 | 資源限制 |
| `CAP_SYS_TIME` | 25 | 系統時鐘 |
| `CAP_SYS_TTY_CONFIG` | 26 | TTY 配置 |
| `CAP_LEASE` | 28 | 檔案租約 |
| `CAP_AUDIT_WRITE` | 30 | audit 日誌 |
| `CAP_AUDIT_CONTROL` | 30 | audit 控制 |

**capset 安全規則**：
- `set_permitted(mask)`：新 permitted = mask & bounding，若 eff 中有不在新 permitted 的位元則清除
- `set_effective(mask)`：新 effective = mask & permitted
- `set_inheritable(mask)`：新 inheritable = mask & bounding

### seccomp (cBPF 過濾器)

實作 Linux `SECCOMP_SET_MODE_FILTER`，使用 classic BPF (cBPF) 指令集：

```rust
#[repr(C)]
pub struct SockFilter {
    pub code: u16,  // BPF 指令碼
    pub jt: u8,     // jump if true
    pub jf: u8,     // jump if false
    pub k: u32,     // 通用欄位
}
```

**支援的 BPF 指令類別**：

| 類別 | 用途 |
|------|------|
| `BPF_LD` (0x00) | 載入資料 — 支援 `BPF_IMM`(常數)、`BPF_ABS`(絕對定址)、`BPF_IND`(間接定址) |
| `BPF_JMP` (0x05) | 條件跳躍 — 支援 `JA`(無條件)、`JEQ`(相等)、`JGT`(大於)、`JGE`(大於等於)、`JSET`(位元測試) |
| `BPF_RET` (0x06) | 回傳結果 — `SECCOMP_RET_ALLOW`(0x7fff0000) 或 `SECCOMP_RET_KILL_PROCESS`(0x80000000) |
| `BPF_ALU` (0x04) | 算術運算 — 支援 `ADD`、`OR`、`AND`、`XOR` |
| `BPF_MISC` (0x07) | 暫存器傳遞 — `TAX`(A→X)、`TXA`(X→A) |

**BPF 解釋器**：採用 **instruction-pointer while loop**（非 for-each with broken jumps），能正確解析跳躍目標：

```rust
let mut pc = 0;
while pc < self.filter.len() {
    let inst = &self.filter[pc];
    // ... 執行指令 ...
    match cls {
        BPF_JMP => { pc += jump_offset + 1; }
        BPF_RET => { return inst.k; }
        _ => { pc += 1; }
    }
}
```

**seccomp 檢查 hook**：在 `syscall.rs` 的系統呼叫分派邏輯中，每個 syscall 執行前呼叫 `seccomp_check()`：

```rust
// syscall.rs dispatch
if seccomp::seccomp_check(num) == SeccompAction::Kill {
    return sys_kill_proc(...);
}
Syscall::Seccomp => sys_seccomp(&args),  // 跳過自身檢查
```

syscall 144 (seccomp 本身) 跳過檢查，避免自殺。

### 系統呼叫

| 編號 | 名稱 | 功能 |
|------|------|------|
| 142 | `capget` | 讀取 process 的 3 組 capability sets (effective, permitted, inheritable) |
| 143 | `capset` | 設定 process 的 3 組 capability sets |
| 144 | `seccomp` | 設定 seccomp 策略 (`SECCOMP_SET_MODE_FILTER=2`) |

### per-process 狀態

Capabilities 和 seccomp 狀態儲存在 `ProcData` 中：

```rust
// proc.rs
pub struct ProcData {
    pub caps: SpinLock<CapabilityState>,
    pub seccomp: SeccompState,
    ...
}
```

初始值：所有 cap 位元皆為 1（完全權限），seccomp 為 `Disabled`。

## 使用者空間包裝

`user/src/syscall.rs` 提供 raw + safe wrappers：
- `raw::capget(hdrp, datap)` — 使用 syscall 142
- `raw::capset(hdrp, datap)` — 使用 syscall 143
- `raw::seccomp(op, flags, args)` — 使用 syscall 144

`xv8rust/xv8-libc/src/raw.rs` 提供相同包裝供 POSIX 工具鏈使用。

## 測試結果

```
test capability ... ok
test seccomp ... ok
```

**capability 測試**：
1. `capget` 讀取預設 caps — 驗證所有位元皆為 1 (u32 max)
2. `capset` 清除 `CAP_NET_RAW` (bit 13)
3. `capget` 驗證 effective 與 permitted 已更新

**seccomp 測試**：
1. 載入白名單 BPF 過濾器（只允許 read/write/exit/exit_group）
2. fork 子 process
3. 子 process 嘗試 `open()` — 被 seccomp kill
4. 父 process 檢查子 process 的 exit status 非零

## 已知限制

1. Capabilities 僅儲存狀態，尚未掛鉤到實際的權限檢查點（如檔案存取、socket 操作）
2. seccomp 無 `SECCOMP_RET_ERRNO` 支援（僅有 ALLOW/KILL）
3. 無 `SECCOMP_FILTER_FLAG_TSYNC`（執行緒同步）支援
4. 無 `SECCOMP_SET_MODE_STRICT` 支援（僅有 FILTER mode）
5. BPF 暫存器記憶體未實作完整的 16 個 cell（seccomp 場景不需要）
