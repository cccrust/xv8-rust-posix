# v5.5 容器網路 (veth pair)

## 目標

在 xv8 中實作虛擬 Ethernet 設備 (veth pair)，為容器網路提供基礎通道能力。veth pair 是一對虛擬網路介面，一端在 host 命名空間，另一端在 container 命名空間，彼此像一條虛擬網路線般相連。

## 設計

### VethEndpoint

每個 veth pair 包含兩個 `VethEndpoint`，均實作 `NetDevice` trait：

```rust
struct VethEndpoint {
    peer_id: OnceLock<InterfaceId>,  // 對方的介面 ID
    own_id: OnceLock<InterfaceId>,   // 自己的介面 ID
}

impl NetDevice for VethEndpoint {
    fn transmit(&self, packet: &[u8]) -> Result<(), NetError> {
        // 直接將封包送入 peer 的 incoming queue
        net::enqueue_incoming(*peer, Box::from(packet))
    }
    fn needs_arp(&self) -> bool { false }   // 不須 ARP
    fn needs_dhcp(&self) -> bool { false }  // 不須 DHCP
}
```

傳送路徑：
```
Container app → transmit() → enqueue_incoming(peer_id, packet)
    → net_thread → receive() → IPv4/TCP/UDP dispatch
```

### 隨機 MAC 位址

使用 xv8 的 PCG 隨機數產生器 (`rng::rand_bytes`) 產生 MAC 位址，並設定本地管理位元 (bit 1) 以標示為虛擬介面：

```rust
fn random_mac() -> MacAddr {
    let mut buf = [0u8; 6];
    rng::rand_bytes(&mut buf);
    buf[0] = (buf[0] & 0xfe) | 0x02;  // 設 local/admin, 清 multicast
    MacAddr(buf)
}
```

### ioctl 介面

透過 ioctl 命令 `XV8_VETH_CREATE` (值 100) 建立 veth pair，需在一個 socket fd 上呼叫：

```rust
Ioctl::XV8_VETH_CREATE = 100
```

arg 指向 32 bytes 的結構，包含兩個 16-byte 的介面名稱：

```rust
#[repr(C)]
struct VethReq {
    name1: [u8; 16],  // 第一個介面名稱 (null-terminated)
    name2: [u8; 16],  // 第二個介面名稱 (null-terminated)
}
```

ioctl 處理流程 (`file.rs`)：
1. 從使用者空間拷貝 32 bytes 的請求結構
2. 解析兩個 null-terminated 名稱字串
3. 呼叫 `create_pair(name1, name2)` 建立 veth pair
4. 回傳 0

### InterfaceConfig 變更

因 veth 介面在執行期動態建立，`InterfaceConfig.name` 的型別從 `&'static str` 改為 `String`。

### 建立流程

```rust
pub fn create_pair(name1: &str, name2: &str) -> Result<(InterfaceId, InterfaceId), NetError> {
    let dev1 = Arc::new(VethEndpoint { peer_id: OnceLock::new(), own_id: OnceLock::new() });
    let dev2 = Arc::new(VethEndpoint { peer_id: OnceLock::new(), own_id: OnceLock::new() });

    // 註冊兩個介面（自動分配 InterfaceId）
    let id1 = interface::register_interface(InterfaceConfig { name: name1, ... }, dev1);
    let id2 = interface::register_interface(InterfaceConfig { name: name2, ... }, dev2);

    // 互相連結 peer 參照
    dev1.peer_id.initialize(id2);
    dev2.peer_id.initialize(id1);

    Ok((id1, id2))
}
```

4. 輸出 "veth test passed"

## 已知限制

1. 無軟體 bridge 支援 (多個 veth 無法互通)
2. 無 NAT/SNAT 支援 (容器無法存取外部網路)
3. veth 建立後無 IP 設定 (需手動設定)
4. 無 way to list available interfaces (需 `/proc/net` 或類似機制)
5. Bridge 與 NAT 為 v5.5 的預期功能，待後續版本補上
