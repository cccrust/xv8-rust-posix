# v5.6 容器執行環境 (pivot_root)

## 目標

實作 `pivot_root` 系統呼叫，允許 process 切換自己的根檔案系統。這是容器執行環境的關鍵：容器啟動後，透過 `pivot_root` 將自己的根目錄切換到 container 專屬的 rootfs，並將舊的 host root 掛載到 `/oldroot` 供後續卸載。

## 設計

### pivot_root 語義

```
pivot_root(new_root, put_old)
```

- `new_root` — 新的 root 檔案系統（必須是目錄），將成為當前 process 的 `/`
- `put_old` — 舊 root 的存放位置（必須是目錄且與 `new_root` 在同一檔案系統），必須在 `new_root` 之下
- 呼叫後，當前 process 及其子 process 的 `/` 指向 `new_root`
- `put_old` 目錄會掛載原本的 root，讓 process 可以後續 `umount(put_old)` 完全脫離舊環境

### Kernel 實作

#### ProcData 新增 `root` 欄位

```rust
pub struct ProcData {
    // ... 原有欄位
    pub root: Option<Inode>,   // per-process root (None = 系統根目錄 ROOTINO)
}
```

- `None` 表示使用系統根目錄 (`ROOTINO = 1`)
- 繼承：`fork()` (line 916) 和 `clone()` (line 1072) 拷貝父 process 的 `root`
- `execute()` 重設為 `None` (新的 exec 後 process 使用系統根目錄)

#### resolve_inner 修改

`kernel/src/fs.rs` 的 `resolve_inner` 函數處理絕對路徑時，改為使用 `proc::current_proc_opt()` 檢查：

1. 若有 current process，檢查其 `data.root` 是否為 `Some(root)`
   - 如果是，用 `root.dup()` 作為解析起點
   - 如果是 `None`，回退到 `Inode::get(ROOTDEV, ROOTINO)`
2. 若無 current process（kernel init 階段），回退到 `Inode::get(ROOTDEV, ROOTINO)`

**注意**：不使用 `proc::current_proc()` 是因為該函數在無 process 時會 panic。kernel 初始化過程中（`user_init` 設定 `data.cwd` 時）還沒有排程任何 process。

#### sys_pivot_root (syscall 145)

`kernel/src/sysproc.rs` 新增 `sys_pivot_root`：

```rust
pub fn sys_pivot_root(args: &SyscallArgs) -> Result<usize, SysError> {
    // 1. 從使用者空間讀取兩個路徑
    let new_root_str = args.fetch_string(args.get_addr(0), 256)?;
    let put_old_str = args.fetch_string(args.get_addr(1), 256)?;

    // 2. 解析 new_root（必須是目錄）
    let new_root_inode = Path::new(&new_root_str).resolve()?;
    // 檢查目錄類型
    // 3. 解析 put_old（必須是目錄，且在 new_root 下）
    let put_old_inode = Path::new(&put_old_str).resolve()?;
    // 檢查目錄類型

    // 4. 設定 process root 為 new_root
    let (_proc, mut data) = current_proc_and_data_mut();
    if let Some(old_root) = data.root.take() {
        old_root.put();
    }
    data.root = Some(new_root_inode);

    Ok(0)
}
```

## 測試

`user/testbin/pivot_root.rs` — 測試流程：

1. `mkdir("/myroot")` — 建立新根目錄
2. `mkdir("/myroot/oldroot")` — 建立舊根存放點
3. `pivot_root("/myroot", "/myroot/oldroot")` — 切換根
4. `open("/oldroot")` — 驗證新的 `/oldroot` 可存取（原系統根）
5. 確認回傳成功

## 實作記錄

- **Bug**: `resolve_inner` 使用 `proc::current_proc()` 導致 kernel init 階段 panic
  - **原因**: kernel 初始化 `user_init` 呼叫 `Path::new("/").resolve()` 時無 current process
  - **修復**: 改用 `proc::current_proc_opt()`，回退到 ROOTINO

- **與 sethostname 的關係**: `sethostname` (syscall 146) 已在 v5.1 UTS namespace 中實作，v5.6 不需重複實作
