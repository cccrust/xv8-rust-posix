# v3.3 — thread::Builder + Environment Safety

## 目標

實作 `thread::Builder`（name、stack_size）、`Thread::name()` accessor，將 `thread::spawn()` 改為 Builder 的 shortcut，並依 Rust std 慣例將 `env::set_var`/`remove_var` 標為 `unsafe`，以及補強 spawn 錯誤處理。

## 設計總覽

### Builder Pattern

Rust std 的 `thread::spawn()` 底層使用 `thread::Builder`：

```rust
// 目前寫法（直接 panic）
thread::spawn(|| { ... });

// Builder 寫法（可設 name、stack_size、處理錯誤）
Builder::new()
    .name("worker".into())
    .stack_size(65536)
    .spawn(|| { ... })
    .expect("spawn failed");
```

## P1 — Builder Struct

### 1.1 Builder

```rust
pub struct Builder {
    name: Option<String>,
    stack_size: usize,
}

impl Builder {
    pub fn new() -> Builder {
        Builder { name: None, stack_size: DEFAULT_STACK_SIZE }
    }

    pub fn name(mut self, name: String) -> Builder {
        self.name = Some(name);
        self
    }

    pub fn stack_size(mut self, size: usize) -> Builder {
        self.stack_size = size;
        self
    }

    pub fn spawn<F, T>(self, f: F) -> io::Result<JoinHandle<T>>
    where
        F: FnOnce() -> T + Send + 'static,
        T: Send + 'static,
    {
        // 建立 join pipe
        // 若有 name，建立 CString 並洩漏到 TCB
        // sbrk(self.stack_size) — 使用 Builder 指定的 stack size
        // clone_tls(CLONE_VM | CLONE_SIGHAND | CLONE_SETTLS, stack_top, 0, tcb_ptr)
        // 回傳 io::Result
    }
}

impl Default for Builder {
    fn default() -> Builder { Builder::new() }
}
```

### 1.2 spawn() shortcut

`thread::spawn()` 現在使用 `Builder::default()`：

```rust
pub fn spawn<F, T>(f: F) -> JoinHandle<T>
where
    F: FnOnce() -> T + Send + 'static,
    T: Send + 'static,
{
    Builder::new().spawn(f).expect("spawn failed")
}
```

保留原本的 panic 行為（與 Rust std 一致）。

## P2 — Thread::name()

### 2.1 TCB 修改

TCB 加入 `name` 欄位（指向洩漏的 CString）：

```rust
#[repr(C)]
struct Tcb {
    park: AtomicU32,
    name: usize,    // CString ptr, 0 = no name
    args_ptr: usize,
}
```

Builder 在 spawn 時將 name 存為 CString 並洩漏（`core::mem::forget`），確保 TCB 中的指標在 child thread 執行期間有效。

### 2.2 Thread struct

```rust
pub struct Thread {
    id: usize,
    join_fd: usize,
    park_addr: usize,
    name: Option<String>,
}

impl Thread {
    pub fn name(&self) -> Option<&str> {
        self.name.as_deref()
    }
}
```

### 2.3 current().name()

`current()` 從 tp 指向的 TCB 中讀取 name pointer，轉為 `&str`：

```rust
fn current_name() -> Option<String> {
    let tp: usize;
    unsafe { core::arch::asm!("mv {}, tp", out(reg) tp) };
    if tp == 0 { return None; } // 主執行緒無 TCB → no name
    unsafe {
        let tcb = &*(tp as *const Tcb);
        if tcb.name == 0 { None }
        else {
            let cstr = CStr::from_ptr(tcb.name as *const c_char);
            Some(cstr.to_str().ok()?.to_string())
        }
    }
}
```

## P3 — env::set_var / remove_var 標為 unsafe

### 3.1 Rust std 慣例

自 Rust 2024 edition 起，`std::env::set_var` 與 `remove_var` 被標為 `unsafe`，因為：
- 在 multi-thread 環境下修改 env 是 data race（未同步）
- 對 `env::var()` 的併發讀取可能看到不一致的狀態
- 部分平台實作非 thread-safe

### 3.2 修改內容

```rust
// xv8rust/xv8-user-std/src/env.rs
pub unsafe fn set_var(key: &str, value: &str) { ... }
pub unsafe fn remove_var(key: &str) { ... }
```

並修正內部呼叫者 `set_current_dir()`：

```rust
pub fn set_current_dir(path: &Path) -> io::Result<()> {
    // ...
    unsafe { set_var("PWD", path_str); }
    Ok(())
}
```

### 3.3 POSIX sh.rs 修正

POSIX shell 在 riscv64 上透過 `xv8_user_std::env` 呼叫 `set_var`，兩個呼叫點加上 `unsafe` block：

```rust
// posix/tools/src/bin/sh.rs
unsafe { env::set_var(name, val); }
```

## P4 — Spawn Error Handling

### 4.1 pipe 失敗

若 `xv8_libc::pipe()` 回傳負值，回傳 `io::Error`。

### 4.2 sbrk 失敗

`xv8_libc::sbrk()` 在記憶體不足時回傳負值（-1），此時需清理已分配的資源（Args、TCB、pipe FD），回傳 `io::Error`。

### 4.3 clone_tls 失敗

`xv8_libc::clone_tls()` 在 clone 失敗（如 NPROC 已滿）時回傳負值，清理資源後回傳 `io::Error`。

```rust
pub fn spawn<F, T>(self, f: F) -> io::Result<JoinHandle<T>> {
    // pipe creation
    if xv8_libc::pipe(join_fds.as_mut_ptr()) < 0 {
        return Err(io::Error::new(ErrorKind::Other, "spawn: pipe failed"));
    }
    // ... setup args, tcb ...
    // sbrk
    let stack_base = xv8_libc::sbrk(self.stack_size as isize);
    if stack_base < 0 {
        // cleanup: free args, tcb, close fds
        return Err(io::Error::new(ErrorKind::Other, "spawn: sbrk failed"));
    }
    // clone
    let tid = xv8_libc::clone_tls(flags, stack_top, 0, tcb_ptr as usize);
    if tid < 0 {
        // cleanup
        return Err(io::Error::new(ErrorKind::Other, "spawn: clone failed"));
    }
    // success
    Ok(JoinHandle { ... })
}
```

### 測試結果

8/8 QEMU core tests pass（含 thread test）。

### Known Limitations

1. 主執行緒無 TCB，`current().name()` 永遠回傳 `None`
2. name CString 透過 `core::mem::forget` 洩漏，永不釋放（每次 spawn 都有 name 時會累積）
3. `thread::spawn()` 仍使用 assert/panic 的快捷版，若要 `io::Result` 需用 `Builder::spawn()`
