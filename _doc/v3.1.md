# v3.1 — Process + Wait Correctness

## 目標

修復 `process::Command` 的 wait/read_output 行為，避免 pipe deadlock，實作正確的 `waitpid` 模擬、`try_wait`、`wait_with_output` 與 `ExitStatus` 快取，並補強 spawn 錯誤處理。

## 設計總覽

xv8 的 process module 依賴 `xv8_libc::wait()`（等同 Linux `wait(NULL)`），不支援 `waitpid()` 或 `WNOHANG`。這導致：
1. `wait()` 可能收到非對應 child 的 exit event
2. `wait_with_output()` 在 stdout/stderr 滿 pipe buffer 時 deadlock
3. `try_wait()` 沒有 non-blocking 實作
4. 多次呼叫 `wait()` 會 panic（第二次找不到 child）
5. `spawn()` 失敗時關閉 pipe 不完整

## P1 — waitpid 模擬

### 1.1 `Child::wait()` — PID 過濾

xv8 的 `wait()` syscall 回傳任意 child exit。為模擬 `waitpid(pid, ...)`，多次呼叫 `wait()` 直到 PID 匹配：

```rust
pub fn wait(&mut self) -> io::Result<ExitStatus> {
    if let Some(status) = self.status.take() {
        return Ok(status);
    }
    loop {
        let (pid, status) = xv8_libc::wait();
        if pid == self.id() as isize {
            self.status = Some(ExitStatus(status));
            return Ok(ExitStatus(status));
        }
        // 非匹配 child — 在 xv8 上只能 busy loop（無 waitpid）
    }
}
```

限制：xv8 kernel 無 `WNOHANG` 支援，`wait()` 是 blocking call。若有多個 child process，其中一個 exit 會讓其他 child 的 `wait()` 收到錯誤的 PID，導致 busy loop。

### 1.2 `try_wait()` — Non-blocking

```rust
pub fn try_wait(&mut self) -> io::Result<Option<ExitStatus>> {
    if let Some(status) = self.status {
        return Ok(Some(status));
    }
    // 用 waitpid 模擬：WNOHANG = 1
    match xv8_libc::waitpid(-1, 1) { // pid=-1, flags=WNOHANG
        -1 => Ok(None),     // ECHILD
        -11 => Ok(None),    // EAGAIN
        pid if pid as u32 == self.id() => {
            let status = /* 從 waitpid 回傳值解析 */;
            self.status = Some(ExitStatus(status));
            Ok(Some(ExitStatus(status)))
        }
        _ => Ok(None), // 非對應 child
    }
}
```

實作上利用 `poll()` 檢查 child 是否已 exit（SIGCHLD epoll），避免 blocking wait。

### 1.3 ExitStatus 快取

```rust
pub struct Child {
    pub stdout: Option<File>,
    pub stderr: Option<File>,
    pub stdin: Option<File>,
    status: Option<ExitStatus>, // 快取，首次 wait 後填入
    // ...
}

impl Child {
    pub fn wait(&mut self) -> io::Result<ExitStatus> {
        if let Some(status) = self.status {
            return Ok(status);
        }
        let (pid, code) = xv8_libc::wait();
        assert_eq!(pid as u32, self.id());
        self.status = Some(ExitStatus(code));
        Ok(ExitStatus(code))
    }

    pub fn try_wait(&mut self) -> io::Result<Option<ExitStatus>> {
        if let Some(status) = self.status {
            return Ok(Some(status));
        }
        Ok(None) // xv8 簡化: 不回傳 child exit 以外的結果
    }
}
```

## P2 — Pipe Deadlock 修復

### 2.1 問題分析

`wait_with_output()` 的典型實作：
```
1. 讀 stdout（block 直到 EOF → child close write end）
2. 讀 stderr（同上）
3. 呼叫 wait()
```

若 child 的 stdout 輸出超過 pipe buffer（xv8 預設 512 bytes），child 在 write 時會 block。但 parent 仍在 step 1 的 read 中（還沒來得及讀），雙方 deadlock。

### 2.2 poll-based read_output

```rust
pub fn wait_with_output(mut self) -> io::Result<Output> {
    use xv8_libc::PollFd;

    let mut stdout = Vec::new();
    let mut stderr = Vec::new();
    let mut done_stdout = self.stdout.is_none();
    let mut done_stderr = self.stderr.is_none();

    loop {
        let mut fds = Vec::new();
        if let Some(ref fd) = self.stdout {
            fds.push(PollFd { fd: fd.as_raw(), events: POLLIN, revents: 0 });
        }
        if let Some(ref fd) = self.stderr {
            fds.push(PollFd { fd: fd.as_raw(), events: POLLIN, revents: 0 });
        }

        let timeout = if done_stdout && done_stderr { 0 } else { -1 };
        let n = xv8_libc::poll(fds.as_mut_ptr(), fds.len(), timeout);

        if n < 0 { break; }
        if done_stdout && done_stderr { break; }

        for (i, pollfd) in fds.iter().enumerate() {
            if pollfd.revents & POLLIN == 0 { continue; }
            let mut buf = [0u8; 4096];
            let fd = if i == 0 { &self.stdout } else { &self.stderr };
            if let Some(ref file) = fd {
                let n = file.read(&mut buf).unwrap_or(0);
                if n == 0 {
                    if i == 0 { done_stdout = true; }
                    else { done_stderr = true; }
                } else {
                    if i == 0 { stdout.extend_from_slice(&buf[..n]); }
                    else { stderr.extend_from_slice(&buf[..n]); }
                }
            }
        }
    }

    let status = self.wait()?;
    Ok(Output { status, stdout, stderr })
}
```

關鍵：在 `wait()` 之前先用 `poll()` 非阻塞地讀完 stdout/stderr，避免 pipe buffer 滿時 deadlock。

## P3 — Spawn Error Handling

### 3.1 Pipe Cleanup on Fork Failure

```rust
pub fn spawn(&mut self) -> io::Result<Child> {
    let (stdout_r, stdout_w) = pipe()?;
    let (stderr_r, stderr_w) = pipe()?;

    match fork() {
        -1 => {
            // fork 失敗：關閉所有剛開的 pipe FD
            close(stdout_r); close(stdout_w);
            close(stderr_r); close(stderr_w);
            return Err(io_error("fork failed"));
        }
        0 => {
            // child: 複製 pipe write end 到 stdout/stderr
            dup2(stdout_w, 1); close(stdout_w); close(stdout_r);
            dup2(stderr_w, 2); close(stderr_w); close(stderr_r);
            exec(...);
        }
        pid => {
            // parent: 關閉 write end
            close(stdout_w); close(stderr_w);
            Ok(Child {
                id: pid,
                stdout: Some(File(stdout_r)),
                stderr: Some(File(stderr_r)),
                stdin: None,
                status: None,
            })
        }
    }
}
```
