# v1.6 — riscv64 Crossterm Compilation

## 目標

讓 crossterm 能在 `riscv64gc-unknown-none-elf` 上編譯，使 vi/vim 可在 xv8 內執行。

## 問題

Crossterm 0.29.0 高度依賴 `std` 和平台特定 API（`cfg(unix)` / `cfg(windows)`），`riscv64gc-unknown-none-elf` 兩者都不是。此外，xv8-user-std 只提供 POSIX 工具所需的最小 std 子集，缺少 crossterm 依賴的許多基礎設施。

## 修改

### xv8-user-std 擴充

| 檔案 | 修改 |
|------|------|
| `src/lib.rs` | 新增 `pub mod result`（re-export `core::result`） |
| `src/io.rs` | `Write` trait 新增 `by_ref()` 方法 |

### crossterm 修改

| 檔案 | 修改 |
|------|------|
| `Cargo.toml` | 為 riscv64 新增 `std = { package = "xv8-user-std" }` 相依 |
| `src/lib.rs` | event 模組保持 `#[cfg(all(feature = "events", not(target_arch = "riscv64")))]` |
| `src/tty.rs` | `isatty(fd)` 呼叫修正為 `fd as usize`（xv8-libc 的 `isatty` 接受 `usize`） |
| `src/cursor/sys/riscv64.rs` | 新增 `SetCursorStyle` 實作 |
| `src/terminal/sys/riscv64.rs` | 新增 `supports_keyboard_enhancement()` stub |

### vim.rs 修改

| 修改 | 說明 |
|------|------|
| 將 `use crossterm::event` 分離為獨立 import，並加上 `#[cfg(not(target_arch = "riscv64"))]` | 避免 riscv64 上 event 模組不存在 |
| 新增 `RiscvKey` 列舉 | riscv64 上替代 `KeyCode` 的本地類型 |
| 新增 `#[cfg(target_arch = "riscv64")]` 版本的 `process_keypress` | 直接從 stdin 讀取位元組 |
| 重複 `process_normal`/`process_insert`/`process_command` 方法 | 分別提供 riscv64 和 host 版本 |

## 驗收

```bash
# riscv64 編譯成功（所有工具 + crossterm）
cargo build --release -p tools --target riscv64gc-unknown-none-elf --features crossterm

# host 編譯 + 測試全部通過
cargo build -p tools --release
cd posix && bash test.sh
# Results: PASS: 33 (shell) + PASS: 21 (core tools)
```

## 已知限制

- **event 模組**：vi/vim 在 riscv64 上不使用 crossterm 的事件系統（需要複雜的 `poll`/`read` 基礎設施）。改用原始 stdin 讀取，支援基本字元輸入。
- **方向鍵/功能鍵**：riscv64 上僅支援基本按鍵（字元、Enter、Backspace、Esc），方向鍵透過 `hjkl` 使用。
- **鍵盤增強模式**：riscv64 上不支援 `supports_keyboard_enhancement()`。
