# net v1.1 — xv8-libc 網路層 + DNS tool 移植

## 狀態 ✅

第一條從 xv8 使用者程式到網路的完整工具鏈已建立：
`dns tool (userspace) → xv8-user-std::UdpSocket → xv8-libc syscall → xv8 kernel UDP stack → E1000 → QEMU user-mode NAT → internet`

## 實作摘要

### 1.1.1：xv8-libc 網路 syscall wrapper ✅

`xv8rust/xv8-libc/src/raw.rs` 已存在 `socket`, `send`, `receive` syscall wrappers：

| 函式 | 對應 kernel syscall |
|------|-------------------|
| `socket(port) -> isize` | `SYS_SOCKET` (#24) |
| `send(fd, buf, len, dest_ip, dest_port) -> isize` | `SYS_SEND` (#25) |
| `receive(fd, buf, len, src_ip, src_port) -> isize` | `SYS_RECEIVE` (#26) |

`SYS_SEND` 和 `SYS_RECEIVE` 均使用 `syscall5`（a0-a4 五個參數）。

### 1.1.2：xv8-user-std `UdpSocket` ✅

`xv8rust/xv8-user-std/src/net.rs` 提供：

- `UdpSocket::bind(port: u16) -> io::Result<Self>`
- `socket.send_to(buf, addr) -> io::Result<usize>`
- `socket.recv_from(buf) -> io::Result<(usize, SocketAddr)>`
- `SocketAddr` 結構（`ip: [u8; 4]`, `port: u16`）+ `parse()` 方法

### 1.1.3：xv8 native DNS binary (`/dns`) ✅

`xv8/user/bin/dns.rs` 使用 native `user` crate syscall API 實作 DNS A record 查詢：

- `dns <server-ip> <domain>` 格式
- 不依賴 `alloc`/`Vec`，全部使用固定陣列
- 含 polling timeout（`receive_timeout`）
- 支援多個 A record 回覆

**檔案異動：**
- `xv8/user/Cargo.toml`：新增 `[[bin]] name = "dns"` 註冊
- `xv8/mkfs.sh`：新增 `target/.../release/dns` 納入 fs.img

**驗證方式：**
```bash
# 在 xv8 shell 中執行
dns 8.8.8.8 example.com
# 預期輸出（example.com 現由 Cloudflare CDN 代管）：
# 172.66.147.243
# 104.20.23.154
```

### 1.1.4：QEMU hostfwd ✅

`xv8/.cargo/config.toml` 加入 `hostfwd=udp::19999-:19999`：

```
-netdev user,id=net0,hostfwd=udp::19999-:19999 \
```

**用途：** host 端可透過 UDP port 19999 送封包到 guest 的 port 19999。例如：

```bash
# Host 送 UDP 到 xv8 guest
echo "hello" | nc -u 127.0.0.1 19999

# xv8 端監聽（待實作 listen 工具）
# net listen 19999
```
