# net v1.0 規劃 — xv8 QEMU 網路整合

## 目標

讓 xv8 在 QEMU 上擁有可運作的網路，並將 `net/` 工具移植到 xv8 執行。
分階段進行，第一階段先讓 xv8 kernel 既有網路棧能在 QEMU 上動起來。

## 階段

### 1.0.1：QEMU 網路後端

**現狀：** xv8 的 QEMU 指令完全沒有 `-nic` 參數，E1000 驅動初始化後沒有實體網卡可通訊。

**修改：** 在 `xv8/.cargo/config.toml` 的 QEMU 參數加入：

```
-nic user,model=e1000
```

`-nic user` 是 QEMU 內建用戶模式 NAT，不需 tap/tun、跨平台（macOS/Linux/Windows 都可用）。

**驗證：**
1. xv8 開機後 DHCP 拿到 IP（10.0.2.x）
2. loopback UDP echo test（既有的 `net` test 通過）
3. `ping 10.0.2.2`（host）可通

### 1.0.2：xv8-libc 網路 syscall wrapper

在 `xv8_std/xv8-libc/src/` 新增：

| 函式 | 對應 kernel syscall |
|------|-------------------|
| `sys_socket(port) -> isize` | `SYS_SOCKET` |
| `sys_send(fd, buf, len, dest_ip, dest_port) -> isize` | `SYS_SEND` |
| `sys_receive(fd, buf, len, src_ip, src_port) -> isize` | `SYS_RECEIVE` |

### 1.0.3：xv8-user-std 網路抽象層

在 `xv8_std/xv8-user-std/` 新增 `net.rs`，提供類似 `std::net` 的介面：

- `UdpSocket`（bind, send_to, recv_from）
- `Ipv4Addr`（封裝）
- 內部透過 xv8-libc syscall wrapper

### 1.0.4：net/ 工具移植

將 `libnet/` 和 `tools/` 改為支援雙後端（std / xv8）：

- `libnet/` 模組 trait 化：`DnsResolver`、`NtpClient`、`IcmpPing`、`TftpClient`、`TcpConnector`
- macOS 上用 `std::net` 實作
- xv8 上用 xv8-user-std 實作
- 條件編譯 `#[cfg(any(target_os = "macos", target_os = "linux"))]` vs `#[cfg(target_os = "none")]`

### 1.0.5：QEMU 整合測試

- TFTP 下載測試（host 開 TFTP server → xv8 下載）
- NTP 查詢測試（xv8 → pool.ntp.org via user NAT）
- DNS 查詢測試（xv8 → 8.8.8.8 via user NAT）

## 非目標

- TCP 移植（xv8 kernel 無 TCP 棧，需要時另開專案）
- 非 xv8 的跨平台移植（Linux/Windows CI 等）
- 完整 `std::net` 相容層（僅最小可用 UDP）

## 專案結構變化

```
xv8_std/
├── xv8-libc/src/
│   ├── raw.rs        + SYS_SOCKET, SYS_SEND, SYS_RECEIVE
│   └── lib.rs        + pub fn socket(), send(), receive()
└── xv8-user-std/src/
    └── net.rs        (新增) UdpSocket、Ipv4Addr
```
