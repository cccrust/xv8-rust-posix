# RISC-V

RISC-V（發音為 "risk-five"）是一個開放原始碼的指令集架構（ISA），也是 xv8 作業系統的目標平台。與 x86 或 ARM 不同，RISC-V 不需要授權費用，非常適合用於教學與作業系統研究開發。

## ISA 概述

RISC-V 採用模組化設計，包含一個基底整數 ISA 加上可選的擴充。基底 ISA（稱為 `I`）提供整數的載入/儲存、算術與控制流程指令。xv8 主要瞄準 `RV64GC` 變體：

- **I**：基底整數指令（64 位元）
- **M**：整數乘除法
- **A**：原子指令，用於同步
- **C**：壓縮 16 位元指令編碼
- **G**：IMAFD 的簡寫（通用擴充）

目標三元組 `riscv64gc-unknown-none-elf` 中的 `rv64gc` 代表：64 位元基底（rv64）、通用（G 包含 IMAFD）、以及 C（壓縮指令）。

## 特權模式

RISC-V 定義了多個特權等級，對作業系統運作至關重要：

- **機器模式（M）**：最高特權，用於開機和韌體。`mret` 指令從 M 模式 trap 返回。
- **監督者模式（S）**：xv8 核心執行所在的模式。`sret` 指令從 S 模式 trap 返回。
- **使用者模式（U）**：使用者程式執行的模式。

特權模式決定了哪些指令和控制狀態暫存器（CSR）可以存取。`medeleg` 和 `mideleg` 暫存器允許將特定的 trap 委派給較低特權等級，這對系統呼叫處理至關重要。

## 控制與狀態暫存器（CSR）

RISC-V 大量使用 CSR 來進行系統控制。xv8 重要的 CSR 包括：

- `mstatus`：機器狀態，追蹤中斷啟用狀態與先前的特權模式
- `mie`：機器中斷啟用
- `mip`：機器中斷待處理
- `mtvec`：機器 trap 向量（trap 發生時跳躍的目的地）
- `mepc`：機器例外程式計數器（trap 時儲存）
- `mcause`：機器原因（什麼觸發了 trap）
- `stvec`：監督者 trap 向量
- `sstatus`：監督者狀態
- `sepc`：監督者例外 PC
- `scause`：監督者原因
- `satp`：監督者位址轉譯與保護（頁表根目錄）

## 位址空間

在監督者模式下，虛擬位址透過 Sv39 分頁機制轉譯（見 [[Virtual-Memory]]）。xv8 的實體位址空間佈局：

- `0x80000000`：RAM 起點（核心文字段）
- `0x80200000`：核心資料/堆積
- `0x88000000`：UART 硬體
- `0x0a000000`：VirtIO 磁碟
- `0x40000000`：E1000 網卡
- `0x0c000000`：PLIC 中斷控制器

## 例外與中斷處理

RISC-V 區分例外（同步，來自指令執行）和中斷（非同步，來自硬體）。兩者都記錄在 `scause`：

- 例外碼：指令位址未對齊、非法指令、載入/儲存錯誤、ecall（系統呼叫）
- 中斷碼：軟體中斷（SI）、計時器中斷（TI）、外部中斷（EI）

`ecall` 指令透過引發例外來觸發系統呼叫，由核心負責處理。這是使用者程式請求核心服務的主要機制。

## ECALL 指令

`ecall` 是系統呼叫的閘道。它不取用明確的運算元，但使用：
- `a7`（x17）：系統呼叫號碼
- `a0-a5`（x10-x15）：參數

在 xv8 中，使用者函式庫（`user/src/syscall.rs`）使用內嵌組語包裝每個 syscall，載入 `a7` 為 syscall 號碼後執行 `ecall`。核心的 trap 處理器解碼 `a7` 後分派到正確的處理函式。

## 為何選擇 RISC-V 開發作業系統？

RISC-V 在學習和實作作業系統方面相較 x86 有諸多優勢：

1. **清晰的 ISA 設計**：沒有分段暫存器或複雜定址模式等歷史包袱
2. **完善的特權架構文件**：M/S/U 模式有清楚的分離定義
3. **開放原始碼**：硬體和軟體工具都可以自由使用（QEMU、Spike、真實硬體）
4. **sv39 分頁**：現代的 39 位元虛擬定址，比 x86 的 PAE 簡單但比基本分頁更強大
5. **生態系成長中**：Linux、BSD 和許多研究用 OS 都能在 RISC-V 上執行
